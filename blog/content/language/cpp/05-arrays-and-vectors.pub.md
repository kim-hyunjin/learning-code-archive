C 스타일 배열은 크기를 컴파일 타임에 고정하고 범위 검사를 전혀 하지 않는 반면, `std::vector`는 크기를 자유롭게 조절하면서도 안전한 접근 수단을 함께 제공합니다. 이 글에서는 둘의 차이와, 벡터가 커질 때 반복자가 무효화될 수 있다는 점을 다룹니다.

## C 스타일 배열

배열은 같은 타입의 값을 고정된 개수만큼 연속된 메모리에 저장합니다.

```cpp
int scores[5] = {90, 85, 77, 100, 60};

std::cout << scores[0] << "\n"; // 90
std::cout << scores[4] << "\n"; // 60

int size = sizeof(scores) / sizeof(scores[0]); // 배열 전체 크기를 원소 크기로 나눠 개수를 구함
```

배열의 크기는 **컴파일 타임에 고정**됩니다. 실행 중에 크기를 늘리거나 줄일 수 없고, 원소 개수를 스스로 알지 못하기 때문에 함수에 넘길 때는 크기를 따로 전달해야 하는 경우가 많습니다.

```cpp
void printArray(int arr[], int size) {
    for (int i = 0; i < size; ++i) {
        std::cout << arr[i] << " ";
    }
}
```

배열은 범위를 벗어난 인덱스에 접근해도 컴파일러나 런타임이 막아주지 않습니다.

```cpp
int arr[3] = {1, 2, 3};
std::cout << arr[5]; // 컴파일은 되지만 정의되지 않은 동작(undefined behavior) — 쓰레기 값이거나 크래시
```

## std::vector

`std::vector`는 크기가 자유롭게 늘어나고 줄어드는 동적 배열입니다. `<vector>` 헤더에 있으며, 실무에서는 원시 배열보다 벡터를 훨씬 많이 씁니다.

```cpp
#include <vector>

std::vector<int> numbers = {1, 2, 3};

numbers.push_back(4);  // 끝에 추가 → {1, 2, 3, 4}
numbers.pop_back();    // 마지막 원소 제거 → {1, 2, 3}

std::cout << "크기: " << numbers.size() << "\n";     // 3
std::cout << "비었나: " << numbers.empty() << "\n";   // 0 (false)

numbers[0] = 100;               // 인덱스 접근 (범위 검사 없음, 배열과 동일한 위험)
numbers.at(1) = 200;             // 범위 검사가 있는 접근, 벗어나면 예외(std::out_of_range) 발생
```

`operator[]`와 `at()`의 차이가 중요합니다. `[]`는 빠르지만 범위를 벗어나면 배열처럼 정의되지 않은 동작이 나고, `at()`은 범위를 검사해서 벗어나면 예외를 던집니다. 디버깅 중이거나 안전이 우선일 때는 `at()`을, 성능이 중요한 반복문 내부에서는 `[]`을 쓰는 식으로 구분합니다.

```cpp
try {
    numbers.at(100) = 1; // out_of_range 예외 발생
} catch (const std::out_of_range& e) {
    std::cout << "범위를 벗어남: " << e.what() << "\n";
}
```

## 벡터가 커지는 방식

`push_back`을 반복하면 내부적으로 필요할 때마다 더 큰 메모리를 새로 할당하고 기존 원소를 복사한 뒤 이전 메모리를 해제합니다. 이 과정에서 **기존에 가지고 있던 반복자(iterator)나 원소의 포인터/참조가 무효화**될 수 있습니다.

```cpp
std::vector<int> v = {1, 2, 3};
int& ref = v[0];
v.push_back(4); // 내부 재할당이 일어나면 ref는 더 이상 유효하지 않을 수 있음
```

미리 필요한 용량을 안다면 `reserve()`로 재할당 횟수를 줄일 수 있습니다.

```cpp
std::vector<int> v;
v.reserve(1000); // 1000개를 담을 공간을 미리 확보 (재할당 방지)
for (int i = 0; i < 1000; ++i) {
    v.push_back(i);
}
```

## 배열 vs 벡터, 언제 무엇을 쓸까

| | 배열 (`int[]`) | `std::vector` |
|---|---|---|
| 크기 | 컴파일 타임 고정 | 실행 중 변경 가능 |
| 메모리 | 스택(지역 변수인 경우) | 힙에 자동 할당/해제 |
| 크기 정보 | 스스로 모름 (따로 전달 필요) | `.size()`로 항상 알 수 있음 |
| 안전한 접근 | 없음 | `.at()` 제공 |

크기가 확실히 고정이고 아주 작은 경우가 아니라면, 대부분의 상황에서 `std::vector`가 더 안전하고 편리한 선택입니다.

## 흔한 실수

- 배열/벡터의 인덱스는 0부터 시작합니다. `size()`가 5인 벡터의 마지막 유효 인덱스는 `4`이지 `5`가 아닙니다.
- 빈 벡터에서 `front()`, `back()`, `[0]`을 호출하면 정의되지 않은 동작입니다. 접근 전에 `empty()`를 확인하는 습관이 필요합니다.
