이 글은 C++ 강의 실습을 정리한 **C++ 학습 노트** 시리즈의 첫 번째 글입니다. 개발 환경과 컴파일 과정 같은 기초부터 시작해, 배열과 벡터, 클래스와 상속, 스마트 포인터, 템플릿과 STL까지 총 21편에 걸쳐 이어집니다. 첫 편에서는 C++ 소스 코드가 실행 파일이 되기까지의 과정과 가장 기본적인 입출력을 다룹니다.

## C++ 코드가 실행 파일이 되기까지

C++ 소스 파일(`.cpp`)은 한 번에 실행 파일이 되는 게 아니라 세 단계를 거칩니다.

1. **전처리(Preprocessing)**: `#include`, `#define` 같은 `#`으로 시작하는 지시문을 처리합니다. `#include <iostream>`은 실제로 `iostream` 헤더 파일의 내용을 그 자리에 그대로 복사해 붙여넣는 것과 같습니다.
2. **컴파일(Compilation)**: 전처리된 코드를 문법적으로 검사하고 기계어에 가까운 오브젝트 파일(`.o`)로 변환합니다. 이 단계에서 나는 에러가 **컴파일 에러**(문법 오류, 타입 오류 등)입니다.
3. **링크(Linking)**: 여러 오브젝트 파일과 라이브러리를 하나로 묶어 실행 파일을 만듭니다. 함수를 선언만 하고 정의(구현)를 빼먹으면 컴파일은 통과하지만 이 단계에서 **링커 에러**(`undefined reference` 등)가 납니다.

이 구분이 중요한 이유는, 에러 메시지의 성격만 봐도 "문법이 틀렸다"인지 "선언은 했는데 구현을 못 찾는다"인지 바로 알 수 있기 때문입니다.

```cpp
// 컴파일 에러 예시: 세미콜론 누락, 타입 불일치 등
int x = "hello"; // error: 문자열 리터럴을 int에 대입할 수 없음

// 링크 에러 예시: 선언만 있고 정의가 없음
void sayHello(); // 선언만 존재

int main() {
    sayHello(); // 컴파일은 통과하지만 링크 단계에서 "undefined reference to sayHello()" 발생
    return 0;
}
```

## 첫 프로그램

```cpp
#include <iostream>

int main() {
    std::cout << "Hello, C++!" << std::endl;
    return 0;
}
```

- `main` 함수는 프로그램의 진입점이며, 운영체제에 반환하는 정수값(종료 코드)을 리턴합니다. `0`은 관례적으로 "정상 종료"를 의미합니다.
- `std::cout`은 표준 출력 스트림, `<<`는 스트림에 값을 흘려보내는 연산자입니다. `std::endl`은 개행 문자를 출력하고 버퍼를 즉시 비웁니다(flush).

## 기본 입출력

```cpp
#include <iostream>
#include <string>

int main() {
    std::string name;
    std::cout << "이름을 입력하세요: ";
    std::cin >> name; // 공백 전까지만 읽는다

    int age;
    std::cout << "나이를 입력하세요: ";
    std::cin >> age;

    std::cout << name << "님은 " << age << "살입니다." << std::endl;
    return 0;
}
```

`std::cin >> name`처럼 `>>`(추출 연산자)는 공백을 기준으로 토큰 하나를 읽습니다. 이름에 공백이 포함되어야 한다면(`"홍 길동"`) `std::getline(std::cin, name)`을 써야 합니다. 이 둘을 섞어 쓸 때 흔히 하는 실수가 있습니다.

```cpp
int age;
std::cin >> age;       // "25\n" 중 "25"만 읽고 개행 문자는 입력 버퍼에 남는다
std::string line;
std::getline(std::cin, line); // 버퍼에 남아있던 개행 문자를 즉시 읽어 빈 줄이 되어버림
```

이런 경우 `std::cin >> age` 뒤에 `std::cin.ignore()`를 호출해 남은 개행 문자를 건너뛰어야 `getline`이 의도대로 동작합니다.

## 주석

```cpp
// 한 줄 주석

/*
   여러 줄에 걸친 주석.
   설명이 길 때 사용한다.
*/
```

주석은 "무엇을 하는지"보다 "왜 이렇게 했는지"를 남길 때 가치가 있습니다. 코드만 봐도 알 수 있는 내용을 굳이 주석으로 반복하지 않는 것이 좋은 습관입니다.

## 흔한 실수

- `std::endl`은 개행뿐 아니라 스트림을 flush하기 때문에, 반복 출력이 많은 루프 안에서 남발하면 성능이 떨어질 수 있습니다. 단순 개행만 필요하면 `"\n"`을 쓰는 것이 더 가볍습니다.
- 링커 에러를 컴파일 에러로 착각해서 문법을 계속 고치는 경우가 많습니다. 메시지에 `undefined reference`, `unresolved external symbol` 같은 문구가 있다면 문법이 아니라 "정의가 빠졌는지, 링크할 파일이 빠졌는지"를 확인해야 합니다.
