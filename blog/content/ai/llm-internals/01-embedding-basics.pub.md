이번 편의 목표는 딱 하나입니다.

> "고양이"라는 토큰의 벡터가 처음에는 아무 의미 없는 숫자였는데, 다음 토큰을 잘
> 맞히는 방향으로 학습하다 보니 **어떻게 숫자가 바뀌는가**를 직접 눈으로 본다.

처음부터 거대한 LLM으로 이걸 보려고 하면 계산이 너무 복잡합니다. 그래서 토큰 3개짜리
아주 작은 언어 모델을 만들어서 봅니다.

## 1. 아주 작은 LLM 만들기

Vocabulary(어휘)가 딱 3개 있다고 합시다.

| ID | 토큰 |
|----|------|
| 0 | 고양이 |
| 1 | 강아지 |
| 2 | 생선 |

그리고 각 토큰을 표현하는 **임베딩 벡터**는 2차원이라고 합시다. 임베딩이란 단어
하나를 숫자 배열(벡터)로 바꾼 것입니다. 처음에는 랜덤하게 정합니다.

```text
고양이 → [0.2, 0.1]
강아지 → [0.1, 0.3]
생선   → [0.4, 0.2]
```

이 숫자에는 아직 아무런 의미가 없습니다. "고양이"가 우연히 `[0.2, 0.1]`을 받았을
뿐, 그 숫자가 고양이를 닮아야 할 이유는 전혀 없습니다.

## 2. 모델에게 문제 내기

학습 데이터에 이런 문장이 있다고 해 봅시다.

```text
고양이는 생선을 먹는다
```

아주 단순하게, 모델에게 이런 문제를 냅니다.

```text
입력: 고양이
정답: 생선
```

모델의 목표는 "고양이라는 정보를 보고 다음에 생선이 나올 것이라고 예측하는 것"
입니다. 실제 LLM이 배우는 것도 본질적으로 이 문제 하나뿐입니다. **바로 앞까지
나온 텍스트를 보고, 다음 토큰이 무엇일지 예측하는 것.** ChatGPT가 문장을 쓰는 것도,
질문에 답하는 것도, 전부 이 "다음 토큰 맞히기"를 아주 많이 반복한 결과입니다.

## 3. 고양이의 임베딩을 꺼낸다

입력이 "고양이"이니, 임베딩 표에서 그 벡터를 그대로 가져옵니다.

```text
X = 고양이의 임베딩 = [0.2, 0.1]
```

이게 이번 문제에서 모델이 받는 입력입니다.

## 4. 아주 간단한 예측기를 만들어 보자

실제 LLM에서는 Transformer가 중간에 아주 복잡하게 끼어들지만(다음 편부터 하나씩
봅니다), 여기서는 임베딩이 어떻게 학습되는지만 보기 위해 단순화합니다.

각 단어가 "다음 단어가 될 가능성"을 판단하는 가중치가 있다고 합시다.

```text
생선의 가중치   → [0.5, 0.8]
강아지의 가중치 → [0.3, 0.2]
고양이의 가중치 → [0.1, 0.1]
```

모델은 입력 벡터와 이 가중치들을 **내적**(같은 자리끼리 곱해서 더하기)해서 점수를
만듭니다.

$$
\text{score}(w) = X \cdot w
$$

"고양이" 입력 `[0.2, 0.1]`과 "생선"의 가중치 `[0.5, 0.8]`을 내적하면,

```text
0.2 × 0.5 + 0.1 × 0.8
= 0.10 + 0.08
= 0.18
```

생선의 점수는 `0.18`입니다.

## 5. 다른 단어도 계산한다

같은 방식으로 강아지, 고양이의 점수도 계산합니다.

```text
강아지: 0.2×0.3 + 0.1×0.2 = 0.06 + 0.02 = 0.08
고양이: 0.2×0.1 + 0.1×0.1 = 0.02 + 0.01 = 0.03
```

결과를 모으면 이렇습니다.

```text
생선   → 0.18
강아지 → 0.08
고양이 → 0.03
```

지금은 생선이 제일 높은 점수입니다.

## 6. 점수를 그대로 확률이라고 하면 안 된다

이 점수를 곧바로 확률처럼 쓰면 안 됩니다. 음수가 나올 수도 있고, 다 더해서 1이
되지도 않기 때문입니다. 그래서 **Softmax**라는 함수를 적용해 점수들을 0~1 사이의,
전부 더하면 1이 되는 확률로 바꿉니다. 개념적으로 이런 확률이 나왔다고 해 봅시다.

```text
생선   → 38%
강아지 → 33%
고양이 → 29%
```

정답은 생선이니, 이상적으로는 모델이 생선에 100%에 가까운 확률을 줘야 합니다.
지금은 38%밖에 안 되니 **아직 잘 못 맞히는** 상태입니다.

## 7. Loss를 계산한다

모델에게 "정답은 생선인데, 너는 38%라고 생각했네"라고 알려줍니다. 이 차이를 숫자로
나타낸 것이 **Loss(손실)** 입니다.

- 정답에 낮은 확률을 줬다면(생선 38%) → Loss가 크다
- 정답에 높은 확률을 줬다면(생선 99%) → Loss가 작다

모델은 학습하면서 이 Loss를 줄이는 방향으로 자신의 숫자들을 바꿔야 합니다.

## 8. 역전파: 어떤 숫자를 얼마나 바꿀지 알아낸다

이제 정말 중요한 부분입니다. 모델이 틀렸으니, "어떤 숫자를 얼마나 바꿔야 하지?"를
계산해야 합니다. 이 계산을 **역전파(Backpropagation)** 라고 부르고, 그 결과로 나오는
"이 숫자를 어느 방향으로 얼마나 바꿔야 Loss가 줄어드는가"라는 정보를 **Gradient**라고
부릅니다. 정확히 어떻게 계산되는지는 다음 편에서 자세히 봅니다. 여기서는

```text
예측 → Loss → 역전파 → 예측기 가중치 → Embedding
```

순서로, Loss에서 출발한 신호가 거꾸로 Embedding의 숫자에까지 전달된다는 것만
기억하면 됩니다.

## 9. "고양이"의 벡터가 바뀐다

역전파로 계산된 "고양이" 임베딩의 Gradient가 예를 들어 `[-0.4, -0.6]`이라고 해
봅시다. 학습률(learning rate)이 0.1이라면, 새 값은 이렇게 계산합니다.

$$
\text{new} = \text{old} - \eta \times \text{Gradient}
$$

```text
첫 번째 숫자: 0.2 - 0.1 × (-0.4) = 0.24
두 번째 숫자: 0.1 - 0.1 × (-0.6) = 0.16
```

```text
학습 전  고양이 → [0.20, 0.10]
                    ↓ 학습
학습 후  고양이 → [0.24, 0.16]
```

숫자가 아주 조금 바뀌었습니다. 이게 **학습 한 번**입니다.

## 10. 그런데 이게 어떻게 "의미"가 되는가

여기가 핵심입니다. 한 번 학습했다고 고양이의 벡터가 "고양이답게" 변하는 것은
아닙니다. 이런 식의 문장을 엄청나게 많이, 반복해서 학습합니다.

```text
고양이는 생선을 먹는다.
고양이가 생선을 좋아한다.
고양이가 생선을 잡았다.
고양이는 동물이다.
고양이가 잠을 잔다.
...
```

그러면 "고양이"라는 벡터가 이런 문장들의 예측에 도움이 되는 방향으로 계속
수정됩니다.

## 11. 강아지도 마찬가지다

"강아지는 생선을 먹는다"라는 데이터가 들어오면 강아지의 임베딩 `[0.1, 0.3]`도
같은 방식으로 학습됩니다. 그리고

```text
강아지는 귀엽다.
강아지가 짖는다.
강아지가 산책한다.
강아지는 동물이다.
```

같은 문장도 계속 등장합니다. 그러다 보면 고양이와 강아지가 **서로 비슷한 특성을
가진 벡터 공간의 위치**를 갖게 될 가능성이 높아집니다. 두 단어가 비슷한 문맥에서
등장하기 때문입니다.

## 12. "의미"를 직접 가르치는 게 아니다

이게 정말 중요합니다. 우리가 모델에게

```text
고양이 = 동물
강아지 = 동물
사과 = 과일
```

이런 사전식 정보를 직접 입력하는 게 아닙니다. 대신 엄청나게 많은 문장을 보여주고,
매번 "다음 토큰을 맞혀 봐"라고 합니다. 모델이 틀릴 때마다

```text
예측 오류 → Loss → Gradient → Embedding 수정
```

을 하고, 이걸 수십억~수조 개 수준의 토큰에 대해 반복합니다. 그러다 보니 모델
내부에 언어의 패턴이 숫자로 나타나게 됩니다.

## 13. 벡터 공간에 구조가 생긴다

학습이 충분히 되었다고 해 봅시다. 아주 단순화해서 2차원으로 그리면 대략 이런
모습이 될 수 있습니다.

```text
↑
│           ● 고양이
│           ● 강아지
│
│
│  ● 사과
│
└──────────────────────→
```

실제 LLM은 2차원이 아니라 훨씬 높은 차원의 공간에서 표현되기 때문에 이렇게 직접
그릴 수는 없습니다. 하지만 핵심은 같습니다. **비슷한 문맥에서 비슷하게 쓰이는
토큰들은 벡터 공간에서도 비슷한 위치를 갖도록 학습될 수 있다.**

## 자동차 운전에 비유하면

이걸 운전 배우기에 비유하면 이해하기 쉽습니다. 처음 운전하는 사람에게 "핸들 →
오른쪽으로 10도, 브레이크 → 30%" 같은 숫자를 알려준다고 해서 그 숫자에 "운전의
의미"가 들어있는 건 아닙니다. 그런데 실제 도로에서

```text
운전 → 실수 → 피드백 → 조정 → 다시 운전 → 실수 → 조정 → ...
```

을 반복하면, 나중에는 상황에 맞는 핸들·브레이크 조작을 자연스럽게 하게 됩니다.
LLM도 같습니다.

```text
랜덤한 숫자 → 예측 → 오차 → Gradient → 숫자 조정 → 반복 → 언어 패턴이 숫자 속에 형성
```

## 정리

이번 편에서 본 것을 한 문장으로 압축하면 이렇습니다.

> 처음에는 랜덤하게 정한다 → 문장을 넣는다 → 다음 토큰을 예측한다 → 정답과
> 비교해 Loss를 계산한다 → 역전파로 가중치를 조정한다 → 이때 Embedding의 숫자도
> 조정된다 → 이 과정을 엄청나게 반복한다.

그런데 아직 한 가지가 마법처럼 남아 있습니다. Loss가 나왔을 때, 수많은 숫자 중에서
정확히 "고양이"의 임베딩 숫자를 **얼마나, 어느 방향으로** 바꿔야 하는지를 컴퓨터가
어떻게 계산하는지는 이번 편에서 결과만 보여주고 넘어갔습니다. 다음 편에서는 미분
→ Gradient → 역전파 → Gradient Descent를 작은 숫자로 직접 계산하며, "학습"이 사실
어떤 계산인지 끝까지 파 봅니다.
