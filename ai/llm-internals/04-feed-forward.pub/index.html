[LLM 내부구조 04] 가져온 정보를 혼자 처리하기: FFN이 하는 일

Attention이 '다른 단어에서 정보를 가져오는 것'이라면, FFN은 '가져온 정보를 혼자 처리하는 것'입니다. Linear-활성화-Linear 구조를 숫자로 직접 계산하고, 왜 필요한지 비유로 정리합니다.

Transformer 한 층을 지금까지 배운 것으로 정리하면 대략 이렇습니다.

Text입력 벡터 → Attention → FFN → 다음 층
  • Attention = 다른 단어의 정보를 가져와서 섞는 곳 (03편)
  • FFN = 가져온 정보를 가지고 각 단어의 벡터를 더 가공하는 곳 (이번 편)

1. 정보를 모았다고 끝이 아니다

“고양이가 생선을 먹었다”에서 “먹었다”가 Attention을 거치며

Text먹었다 → 고양이 정보 + 생선 정보 + 자기 자신의 정보

를 가져왔다고 합시다. 그런데 정보를 가져왔다고 저절로 무언가가 되는 건 아닙니다. 모델 입장에서는 “그래서 이 정보를 가지고 뭘 하지?”가 필요합니다. 여기서 FFN(Feed Forward Network) 이 등장합니다.

2. 사람으로 비유하면

Attention을 자료 조사라고 생각해 봅시다.

Text"고양이가 생선을 먹었다."

Attention: "고양이와 생선이라는 정보를 찾아왔어."

고양이 정보 ──┐
생선 정보   ──┼→ 가져옴
먹었다 정보 ──┘

그러면 FFN은 “좋아, 가져온 정보를 내가 알고 있는 패턴과 비교해서 판단해 보자”에 해당합니다.

TextAttention = 정보 가져오기 / 정보 섞기
FFN       = 가져온 정보 처리하기

3. FFN은 실제로는 작은 신경망이다

FFN은 Feed Forward Network의 약자입니다. Transformer에서 흔히 쓰이는 형태는 대략 이렇게 생겼습니다.

Text입력 벡터 → Linear → 활성화 함수 → Linear → 출력 벡터

여기서 Linear는 01~03편에서 계속 본 것과 똑같은 계산입니다. 벡터에 행렬을 곱하고(때로는 숫자를 더하고) 새로운 벡터를 만드는 것입니다.

4. 벡터 하나를 FFN에 넣어보자

Attention이 끝난 후 이런 벡터가 나왔다고 합시다.

TextX = [2, 3]

FFN의 첫 번째 Linear가 다음과 같이 계산한다고 해 봅시다.

Text첫 번째 값 = 2×1 + 3×2 = 8
두 번째 값 = 2×3 + 3×1 = 9
Text[2, 3] → [8, 9]

5. 활성화 함수가 끼어든다

여기에 ReLU 같은 활성화 함수를 넣을 수 있습니다. ReLU는 아주 단순합니다. 음수면 0, 양수면 그대로.

Text입력:  [-3,  8, -2,  5]
출력:  [ 0,  8,  0,  5]

정리하면 이런 흐름입니다.

Text입력 [2, 3]
  ↓
첫 번째 Linear → [8, 9]
  ↓
활성화 함수 → [8, 9]   (여기선 둘 다 양수라 그대로)
  ↓
두 번째 Linear → 출력

실제 Transformer에서는 ReLU보다 GELU나 뒤에서 볼 SwiGLU 같은 함수를 더 자주 씁니다. 원리는 같습니다. 그냥 통과시키는 게 아니라 값에 따라 정보를 걸러내거나 조절하는 단계가 한 번 더 들어간다는 것이 핵심입니다.

6. 왜 굳이 이렇게 복잡하게 하지?

Attention만 있다면 주로 “다른 토큰의 정보를 얼마나 가져올까?”만 처리하게 됩니다.

Text"고양이가 생선을 먹었다"

먹었다 → 생선 정보 가져오기 → 고양이 정보 가져오기

그런데 가져온 정보를 어떻게 해석하고 변환할지가 필요합니다. FFN이 그 역할을 맡습니다.

TextAttention → 주변 정보를 모음 → FFN → 그 정보를 변환/처리

7. 사람의 사고 과정에 비유하면

“철수가 사과를 먹었다”라는 문장을 읽는다고 해 봅시다.

Attention — “먹었다”를 이해하기 위해 철수는 조금, 사과는 많이 참고합니다. “먹었다라는 행동과 사과가 관련 있구나”라는 정보를 모읍니다.

FFN — 그 정보를 가지고 “아, 이건 사람이 음식을 먹는 상황이구나”처럼, 이미 학습해 둔 패턴을 이용해 정보를 변환하는 데 기여합니다.

물론 실제 LLM이 이런 문장을 머릿속으로 생각하는 건 아닙니다. 전부 숫자 연산으로 일어납니다.

8. “이미 학습해둔 패턴”이 중요하다

FFN도 학습되는 파라미터를 가지고 있습니다.

TextFFN
├── W1
├── b1
├── 활성화 함수
├── W2
└── b2

여기 있는 W1,W2W_1, W_2W1​,W2​ 같은 숫자들이 02편에서 본 것과 똑같은 방식(역전파 → Gradient → Gradient Descent)으로 학습 과정에서 계속 수정됩니다. 따라서 FFN은 학습을 거치면서 “이런 입력 벡터가 들어왔을 때 어떤 정보를 강조하고 어떤 형태로 변환하면 다음 토큰을 잘 예측할 수 있을까”를 점점 잘하게 됩니다.

9. Attention과 FFN, 이렇게 기억하면 된다

물어보는 대상하는 일
Attention다른 사람에게 물어보기“이 상황을 이해하려면 누구의 이야기를 참고해야 하지?”
FFN혼자 생각하기“가져온 정보를 내가 가진 지식/패턴과 관련된 방식으로 변환하자”
  • Attention — “어디서 정보를 가져올까?”
  • FFN — “가져온 정보를 어떻게 처리할까?”

10. 이게 여러 번 반복된다

실제 Transformer는 다음처럼 여러 층으로 구성됩니다.

Text입력 → Attention → FFN → Attention → FFN → Attention → FFN → ...

각 층에서 조금씩 다른 방식으로 정보를 처리합니다. 그래서 처음에는 단순한 벡터였던 것이 Layer 1, Layer 2, … Layer N을 거치면서 점점 복잡한 표현이 됩니다.

11. 실제 규모로 보면: FFN이 더 크다

작은 예제라 체감이 안 되지만, 실제 모델에서 FFN은 Attention보다 파라미터를 더 많이 차지합니다. hidden 차원이 ddd라면, FFN은 보통 ddd를 4d4d4d로 확 늘렸다가 다시 ddd로 줄입니다.

TextFFN:       d → 4d → d     파라미터 ≈ 8d²  (W1, W2 두 개)
Attention: Q,K,V,출력 투영 4개    파라미터 ≈ 4d²

즉 한 블록 안에서 FFN이 Attention보다 대략 두 배 많은 파라미터를 갖습니다. 그렇다고 FFN을 “지식이 저장된 데이터베이스”라고 생각하면 안 됩니다. FFN의 가중치에는 학습된 패턴이 사람이 읽을 수 있는 사전 형태가 아니라 분산된 형태로 녹아 있고, 입력 벡터에 수학적 변환을 적용하면서 그 패턴이 출력에 영향을 주는 구조에 가깝습니다. 참고로 최근 LLaMA나 PaLM 같은 모델은 ReLU/GELU 대신 SwiGLU라는, 값에 따라 정보를 얼마나 흘려보낼지 스스로 조절하는 활성화 함수를 씁니다. 표현력이 더 좋다고 알려져 있습니다.

정리

지금까지 배운 걸 하나로 연결하면 이렇습니다.

Text"고양이가 생선을 먹었다"
  ↓
Tokenizer → Token ID → Embedding → 벡터
  ↓
┌─────────────┐
│ Transformer │
│  Attention  │ ← 주변 정보를 참고
│      ↓      │
│    FFN      │ ← 정보를 변환/처리
└─────────────┘
  ↓ (여러 번 반복)
최종 벡터 → LM Head → 다음 토큰 확률

학습할 때는 이 전체 과정을 거꾸로 타고 올라가면서 02편에서 본 Gradient를 계산해서 Embedding, Wq,Wk,WvW_q, W_k, W_vWq​,Wk​,Wv​, FFN의 W1,W2W_1, W_2W1​,W2​까지 모든 가중치를 수정합니다.

다음 편에서는 지금까지 “Embedding → Attention → FFN”으로 단순화해 둔 그림에, 실제 Transformer를 돌아가게 만드는 나머지 부품들 — 문장을 토큰으로 쪼개는 토큰화, 순서 정보를 알려주는 위치 인코딩, 그리고 깊은 층을 안정적으로 학습시키는 잔차 연결과 LayerNorm — 을 채워 넣습니다.
