# 02. 변수, 타입, 상수

## 기본 타입

C++은 정적 타입 언어라서 변수를 선언할 때 타입을 명시해야 합니다. 대표적인 기본 타입은 다음과 같습니다.

| 타입 | 용도 | 대략적인 크기(플랫폼마다 다름) |
|---|---|---|
| `bool` | 참/거짓 | 1바이트 |
| `char` | 문자 하나 | 1바이트 |
| `int` | 정수 | 4바이트 |
| `long`, `long long` | 더 큰 정수 | 4~8바이트 |
| `float` | 단정밀도 실수 | 4바이트 |
| `double` | 배정밀도 실수 | 8바이트 |

크기가 "대략적"이라고 표현한 이유는 C++ 표준이 정확한 바이트 수를 강제하지 않고 최소 범위만 보장하기 때문입니다. 실제 크기는 `sizeof` 연산자로 확인할 수 있습니다.

```cpp
#include <iostream>

int main() {
    std::cout << "int: " << sizeof(int) << " bytes\n";
    std::cout << "double: " << sizeof(double) << " bytes\n";
    std::cout << "bool: " << sizeof(bool) << " bytes\n";

    int score = 100;
    std::cout << "score 변수: " << sizeof(score) << " bytes\n"; // 타입 대신 변수를 넣어도 된다
    return 0;
}
```

플랫폼 독립적으로 크기가 정확히 필요한 경우(파일 포맷, 네트워크 프로토콜 등)에는 `<cstdint>`의 `int32_t`, `uint64_t` 같은 고정폭 정수 타입을 쓰는 것이 안전합니다.

## 변수 초기화

C++은 변수를 초기화하는 방법이 여러 가지입니다.

```cpp
int a = 10;      // C 스타일 대입 초기화
int b(10);       // 함수 스타일(생성자 스타일) 초기화
int c{10};        // 중괄호 초기화 (uniform initialization)
int d{};          // 값 초기화, 0으로 설정됨
```

중괄호 초기화(`{}`)를 권장하는 이유는 **좁아지는 변환(narrowing conversion)**을 컴파일 타임에 막아주기 때문입니다.

```cpp
int x = 3.14;   // 컴파일은 되지만 3으로 잘림 (경고만 뜨거나 아예 안 뜰 수 있음)
int y{3.14};    // 컴파일 에러: 정수 타입에 실수를 좁혀 넣을 수 없음
```

초기화하지 않은 지역 변수는 쓰레기 값을 가집니다. `int count;`처럼 초기화를 빼먹고 바로 사용하면 실행할 때마다 다른 값이 나올 수 있으니, 선언과 동시에 초기화하는 습관이 중요합니다.

## 전역 변수

함수 밖에서 선언한 변수는 전역 변수가 되며, 프로그램이 시작할 때 자동으로 0(또는 기본값)으로 초기화됩니다.

```cpp
int globalCounter; // 자동으로 0으로 초기화됨

void increment() {
    globalCounter++;
}

int main() {
    increment();
    increment();
    // globalCounter == 2
    return 0;
}
```

편리해 보이지만 전역 변수는 어디서든 수정할 수 있어서 프로그램이 커질수록 "누가 언제 이 값을 바꿨는지" 추적하기 어려워집니다. 정말 여러 함수가 공유해야 하는 상태가 아니라면 지역 변수나 클래스 멤버로 범위를 좁히는 것이 유지보수에 유리합니다.

## 상수(const)

`const`로 선언한 변수는 초기화 이후 값을 바꿀 수 없습니다.

```cpp
const double PI = 3.14159;
const int MAX_USERS = 100;

// PI = 3.14; // 컴파일 에러: const 변수는 재대입 불가
```

상수를 쓰는 이유는 두 가지입니다.

1. **의도 전달**: "이 값은 절대 바뀌지 않는다"는 사실을 컴파일러와 다른 개발자에게 알립니다.
2. **버그 방지**: 실수로 값을 바꾸는 코드를 작성하면 컴파일 단계에서 바로 잡아낼 수 있습니다.

매직 넘버(코드 곳곳에 흩어진 의미 불명의 숫자)를 상수로 뽑아내면 가독성도 함께 좋아집니다.

```cpp
// 나쁜 예
double area = 3.14159 * radius * radius;

// 좋은 예
const double PI = 3.14159;
double area = PI * radius * radius;
```

## 흔한 실수

- `float`과 `double`을 `==`으로 비교하는 것은 위험합니다. 부동소수점은 정확히 표현되지 않는 값이 많아서, 계산 결과가 수학적으로는 같아도 비트 단위로는 다를 수 있습니다. 오차 범위(epsilon)를 두고 비교해야 합니다.
- `unsigned int`끼리 뺄셈해서 음수가 나와야 하는 상황이면, 값이 음수 대신 아주 큰 양수로 감싸(wrap-around) 버립니다. 부호 없는 정수는 "절대 음수가 될 일이 없는 값"(예: 크기, 개수)에만 신중하게 쓰는 것이 안전합니다.
